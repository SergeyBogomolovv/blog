# Между строк

Учебный блог на Next.js и Go. Гости читают посты и комментарии. После регистрации пользователь может публиковать посты, комментировать, просматривать страницы авторов и редактировать свой профиль. Администратор удаляет любые посты, блокирует и разблокирует пользователей.

## Технологии

- Фронтенд: Next.js App Router, TypeScript, Tailwind CSS, shadcn/ui.
- Бэкенд: Go 1.27.2, chi, Squirrel, sqlx.
- База данных: PostgreSQL 17 в Docker Compose; миграции — Goose.
- Авторизация: один JWT access-токен в HttpOnly-cookie.

## Запуск

Нужны Go 1.27.2, Node.js 22+, npm, Docker Compose, Make и OpenSSL.
Команды выполняются из корня проекта.

```sh
make secrets
make install
make db-up
make migrate
make admin
```

`make secrets` создаёт корневой `.env` со случайными паролями и ключами. Существующий файл не перезаписывается. `.env` не попадает в Git; сохраните его вместе с данными БД, поскольку ключ нужен для расшифровки пользовательских данных.

`make admin` запрашивает логин, имя, почту и дважды пароль. Ввод пароля скрыт. Согласие на обработку данных запрашивается только при регистрации на сайте.

Запустите бэкенд и фронтенд в двух отдельных терминалах:

```sh
make backend
```

```sh
make frontend
```

Сайт: **http://localhost:3000**. Go API: `http://127.0.0.1:8080`.
Используйте именно `localhost` для сайта — этот адрес задан в `APP_ORIGIN` для проверки Origin.

Данные БД сохраняются в Docker-томе. `make db-down` останавливает контейнер без удаления данных. Изменение паролей в `.env` не меняет пароли ролей в уже созданной базе.

## Структура

```text
backend/
  cmd/server/       # Запуск HTTP API
  cmd/admin/        # Создание администратора
  cmd/migrate/      # Миграции Goose
  internal/app/     # Сборка компонентов приложения
  internal/config/  # Настройки из .env
  internal/handler/ # HTTP-обработчики и middleware
  internal/service/ # Бизнес-правила и интерфейс репозитория
  internal/repository/ # Запросы Squirrel и выполнение через sqlx
  internal/model/   # Модели данных
  pkg/security/     # Шифрование, HMAC и JWT
  migrations/       # SQL-миграции, встроенные через go:embed
frontend/
  app/              # Страницы, Server Actions и CSS
  components/       # Компоненты интерфейса
  components/ui/    # Компоненты shadcn/ui
  lib/              # Серверный API-клиент и общие типы
db/                 # Первоначальное создание сервисных ролей PostgreSQL
scripts/
  generate-secrets.sh
Makefile
docker-compose.yml
```

Обработчики вызывают сервисы, сервисы работают через интерфейс репозитория. Все запросы репозитория собираются через Squirrel; sqlx выполняет их и заполняет модели. Значения передаются параметрами, отдельно от SQL.

Страницы получают данные через Server Components. Формы отправляются через Server Actions с `useActionState`; после записи обновляются через `revalidatePath`. Next.js читает общий `.env` и обращается к Go напрямую. Адрес API можно задать переменной `BACKEND_URL`.

## Данные и авторизация

JWT действует два часа. При каждом запросе с токеном Go проверяет его подпись, срок, блокировку пользователя и версию сессии в БД. Выход и блокировка отзывают ранее выданные токены.

Пароли хранятся как солёные хеши bcrypt. Логин, email, имя и описание профиля зашифрованы AES-256-GCM. Логин ищется по HMAC-индексу с ограничением уникальности. Публикации и комментарии доступны всем посетителям.

Роль БД `user` используется API с ограниченными правами. Роль `admin` владеет таблицами и используется утилитами миграций и создания администратора. Пароли обеих ролей берутся из `.env`. Docker создаёт роли при первом запуске, а таблицы и права на них создаются миграциями Goose.

Настроены серверная проверка ввода, защитные HTTP-заголовки, проверка Origin и ограничение попыток входа. Веб-регистрация требует согласие на обработку данных; при первом посещении показывается уведомление о необходимых cookie.
