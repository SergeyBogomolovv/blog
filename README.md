# Чистый дом

Учебный сервис приёма заявок на уборку. Главная страница показывает три услуги и поиск. После регистрации и входа пользователь выбирает услугу, адрес и дату, сохраняет заявку и видит свои обращения в личном кабинете.

## Технологии

- Next.js 16 App Router, React 19, TypeScript, Tailwind CSS, Lucide.
- Go 1.27, chi, Squirrel, sqlx; миграции Goose.
- PostgreSQL 17 в Docker Compose.
- Сессии PostgreSQL, подпись HMAC-SHA256, пароли scrypt с индивидуальной солью.

Next.js принимает браузерные запросы на одном адресе и передаёт `/api` локальному Go API.

## Запуск

Нужны Go 1.27+, Node.js 22+, npm, Docker Compose, Make и OpenSSL. Команды выполняются из корня проекта.

```sh
make secrets
make install
make db-up
```

В первом терминале:

```sh
make backend
```

Сервер автоматически создаст таблицы при первом запуске. Он применяет миграции через роль БД `admin`, затем обслуживает API с ограниченной ролью `user`.

Во втором терминале:

```sh
make frontend
```

Откройте **http://127.0.0.1:3107**. Go API слушает `127.0.0.1:8080`; PostgreSQL — `127.0.0.1:5432`. Используйте именно адрес `127.0.0.1:3107`, указанный в `APP_ORIGIN`, иначе защита Origin отклонит формы.

Для запуска собранной версии:

```sh
make build
```

Затем запустите `make backend` и `cd frontend && npm start` в отдельных терминалах. Рекомендуется проверять CSP именно на собранной версии.

`make secrets` создаёт `.env` со случайными секретом сессий и паролями БД. Существующий файл не перезаписывается. Сохраните `.env` вместе с резервной копией базы: неизменный `SESSION_SECRET` необходим для сохранения действующих сессий после перезапуска.

Остановка приложения — Ctrl+C в обоих терминалах. `make db-down` останавливает базу без удаления данных. `docker compose down` тоже сохраняет том; опция `-v` удаляет данные и не нужна при обычной остановке.

## Страницы и сценарии

| Адрес | Назначение |
| --- | --- |
| `/` | Три услуги, безопасный поиск, уведомление о cookie |
| `/register` | Регистрация с ФИО, контактами и согласием |
| `/login` | Вход; после регистрации показывается подтверждение |
| `/dashboard` | Создание и список собственных заявок; гостю нужен вход |
| `/privacy` | Текст согласия и описание необходимых cookie |

Выбор услуги на главной сохраняется при переходах через вход и регистрацию. Регистрация не создаёт сессию автоматически: после неё пользователь переходит на вход. Заявки отображаются от новых к старым. Сообщение об успехе появляется только после подтверждения записи сервером.

## Правила данных

- Фамилия — русские буквы, первая заглавная. Имя допускает две части с заглавными буквами через дефис: `Анна-Мария`.
- Отчество допускает `оглы`, `кызы`, `уулу`, `гызы` через пробел или дефис: `Рашид оглы`.
- Текстовые поля, email и поиск — до 20 символов; адрес — до 100. Пробелы по краям удаляются, пароль сохраняется как введён.
- Логин — только латинские буквы, уникальность без учёта регистра.
- Пароль — от 8 символов, заглавная и строчная латинские буквы, цифра и один из символов `$#@!`. Ограничение в 20 символов к паролю не применяется.
- Телефон — `8(999)123-45-67`. Email — имя, `@` и домен с точкой; начальная, конечная и двойная точки в имени запрещены.
- Согласие обязательно; сохраняются время и версия текста `2026-10-20`.
- Дата уборки — существующая календарная дата не раньше текущего дня по Москве.
- Поиск — обычная подстрока без учёта регистра, только русские и латинские буквы, цифры, пробелы и дефисы.

Клиент проверяет поля перед отправкой; Go повторяет проверку независимо от браузера. Сервер отклоняет неизвестные поля JSON, в том числе попытки передать чужого владельца заявки.

## Хранение и защита

В базе три прикладные таблицы: `users`, `requests`, `sessions`. Владелец заявки определяется только по проверенной сессии. Параметры SQL передаются отдельно от запросов. Пользовательский текст выводится React как текст, без HTML-вставок. База, `.env` и серверные файлы не находятся в каталоге статических ресурсов.

`cleaning.sid` содержит случайный подписанный идентификатор; в БД хранится его SHA-256. Сессия и её cookie действуют 30 минут без активности, продлеваются запросами и переживают перезапуск с сохранёнными БД и секретом. Проверка срока и продление выполняются атомарно. Вход обновляет идентификатор; выход удаляет запись в БД. Отозванная сессия не даёт доступ к API заявок.

Изменения требуют подписанный CSRF-токен, связанный с текущей сессией, совпадение cookie и заголовка `X-CSRF-Token`, правильный Origin и `X-Requested-With: cleaning`. `/api/csrf` выдаёт токен для формы. Общий лимит входа и регистрации — 30 запросов за 15 минут на IP; после превышения — HTTP 429 и `Retry-After`. Go не доверяет клиентскому `X-Forwarded-For`. Прототип рассчитан на один локальный компьютер: все запросы через Next.js приходят с loopback-адреса и разделяют лимит.

`cookie_notice` сохраняется на 180 дней. Все служебные cookie имеют HttpOnly, SameSite=Lax и Path=/. Для локального HTTP Secure выключен, HSTS не отправляется. JSON ограничен 16 КБ как в Next.js, так и в Go.

Передаются CSP, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: no-referrer и Permissions-Policy с отключёнными камерой, микрофоном и геолокацией. API и страницы с данными не кешируются.

В собранной версии CSP разрешает служебные скрипты Next.js по уникальному случайному nonce для каждого ответа. Директивы `unsafe-inline` и `unsafe-eval` отсутствуют; встроенные скрипты без соответствующего nonce запрещены. В режиме разработки разрешены `unsafe-eval` для инструментов Next.js и теги `<style>` без nonce для DevTools через `style-src-elem`; атрибуты `style` остаются запрещены. Ресурсы загружаются с адреса сайта; плагины, встраивание страницы в iframe и отправка форм на чужой адрес запрещены.

## Структура

```text
backend/
  cmd/server/         HTTP-сервер и автоматические миграции
  cmd/migrate/        Управление миграциями
  internal/config/    Конфигурация
  internal/model/     Пользователь, услуга, заявка
  internal/service/   Правила данных и бизнес-логика
  internal/repository/ PostgreSQL через Squirrel и sqlx
  internal/handler/   JSON API, сессии, CSRF, лимит попыток
  pkg/security/       scrypt, подпись сессий и CSRF
  migrations/         Схема базы
frontend/
  app/                Пять страниц, ошибки и API-прокси
  components/         Каталог, формы и кабинет
  lib/                Типы API, клиентская валидация и CSRF
  public/             Локальная иллюстрация
  proxy.ts            CSP с nonce, CSRF-cookie и продление сессии
```

## Резервная копия

```sh
docker compose exec -T db sh -c 'pg_dump -U postgres "$POSTGRES_DB"' > cleanhome-backup.sql
```

Отдельно сохраните `.env`. Восстановление в уже запущенную пустую базу:

```sh
docker compose exec -T db sh -c 'psql -U postgres -d "$POSTGRES_DB"' < cleanhome-backup.sql
```

Не публикуйте копии базы и `.env`.
